# Руководство разработчика Razeru

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `main.cpp`, `resource.*` | Win32-процесс, область уведомлений, опрос раскладки, перехватчик и жизненный цикл |
| `ChromaPlaying.*` | Выбор и воспроизведение сцен Chroma, наложение эффектов, обмен конфигурацией |
| `Razer/` | Импортированная обёртка Razer Chroma API и проверка подписи |
| `RzruUI/` | DLL настроек на MFC, диалоги, ресурсы и сохранение JSON |
| `Animations/` | Включённые ресурсы `.chroma` |
| `third_party/` | Вендоренные заголовочные зависимости и их лицензии |
| `config/` | Конфигурация по умолчанию для инсталлятора |
| `scripts/` | Воспроизводимые сценарии локальной сборки |
| `installer/` | Исходник Inno Setup и сценарий упаковки |
| `.vscode/` | Расширения, правила кодировки и задачи VS Code |

Решение Visual Studio создаёт два собственных бинарных файла:

- `Razeru.exe` управляет скрытым окном сообщений, значком, таймером, глобальным
  перехватчиком клавиатуры и рабочим потоком анимации.
- `RzruUI.dll` реализует настройки и чтение/запись `Razeru.json`.

Они обмениваются `ChromaPlaying::ConfigData` через экспортируемые функции DLL.
Зарегистрированное сообщение Windows (`WM_CONFIG_CHANGED`) просит процесс
приостановиться, перечитать конфигурацию и продолжить работу. Исполняемый файл
обращается к подписанной библиотеке анимаций Razer
`CChromaEditorLibrary64.dll`. Это не системное ядро SDK: в актуальной среде
`RzChromatic64.dll` устанавливается отдельным приложением Razer Chroma.

## Инструменты

Поддерживаемая локальная среда:

- Visual Studio Build Tools 2022 и MSVC v143 для x86/x64;
- Windows 10/11 SDK;
- ATL и MFC нужной архитектуры;
- PowerShell 5.1 или новее;
- Inno Setup 6.7 или новее для упаковки;
- Git и, при желании, Visual Studio Code.

Откройте каталог репозитория в VS Code и примите рекомендации из
`.vscode/extensions.json`. Команды доступны через **Terminal → Run Task**.
Часть старых C++-файлов и ресурсов использует кодовую страницу Windows, поэтому
включён `files.autoGuessEncoding`. Не выполняйте массовую смену кодировки без
проверки: она может повредить локализованные ресурсы.

Одиночный заголовок nlohmann/json 3.12.0 вендорен в `third_party`, поэтому сборка
не зависит от абсолютного пути на машине разработчика.

## Конфигурации сборки

Решение содержит `Debug`, `Release`, `Debug_NoSignatureCheck` и
`Release_NoSignatureCheck` для x86 (платформа проекта `Win32`) и x64. Обычные конфигурации проверяют
Authenticode-подпись среды Razer. Варианты `*_NoSignatureCheck` допустимы только
для контролируемой отладки и не должны распространяться.

Поддерживаемая цель релиза и инсталлятора — x64:

```powershell
.\scripts\build.ps1 -Configuration Release -Platform x64
```

Примеры:

```powershell
.\scripts\build.ps1 -Configuration Debug -Platform x64
.\scripts\build.ps1 -Configuration Release -Platform x86
.\scripts\build.ps1 -Configuration Release -Platform x64 -Analyze
```

Сценарий находит MSBuild через `vswhere.exe`, поэтому Developer Prompt не нужен.
Без `-NoRebuild` выполняется `Rebuild`. Для x64 результат находится в
`<платформа>\<конфигурация>`, для x86 — в `<конфигурация>`; `Win32` принимается
как псевдоним x86. После сборки
копируется только DLL Razer подходящей архитектуры.

## Отладка

Рабочим каталогом отладчика назначьте каталог результата, содержащий EXE,
`RzruUI.dll`, подходящую DLL Razer, `Razeru.json` и `Animations`. Для штатной
инициализации нужны отдельное приложение Razer Chroma с включённым Chroma Apps
и совместимая клавиатура. Synapse необязателен и не является условием теста.
Без внешнего ядра SDK и подключённого оборудования интеграцию Chroma полностью
проверить невозможно.

Основные точки диагностики:

- `CheckActiveLayout` / `GetActiveLayout` — выбор раскладки;
- `KeyboardHookProc` и `EventProcessingThread` — эффекты клавиш;
- `ChromaPlaying::SetActiveSceneEffect` и `PlayingFrameKeyboard` — проигрывание;
- экспортируемые функции `RzruUI.cpp` — обмен конфигурацией.

Обработчик низкоуровневого перехватчика должен оставаться быстрым и
неблокирующим. Общие данные следует защищать мьютексом или атомарными типами; в
перехватчике нельзя выполнять файловые операции и тяжёлые вызовы Chroma.

## Инсталлятор

Полный x64-инсталлятор для текущего пользователя собирается так:

```powershell
.\installer\build-installer.ps1 -AppVersion 1.2.0.4
```

Сценарий упаковки:

1. пересобирает `Release|x64`, если не указан `-SkipBuild`;
2. проверяет наличие полезной нагрузки;
3. при необходимости скачивает закреплённый Microsoft VC++ Redistributable x64;
4. сверяет SHA-256 и Authenticode-подпись Microsoft;
5. проверяет подпись Razer USA Ltd. у включённой DLL;
6. запускает Inno Setup и выводит SHA-256 готового файла.

Ссылка на пакет Microsoft изменяемая. При публикации новой версии нужно
осознанно обновить закреплённый хеш и минимальный номер сборки среды, а затем
проверить чистую установку. Отключать проверку хеша нельзя.

Razer Chroma App — внешняя интерактивная зависимость и не распространяется
внутри Setup. Инсталлятор проверяет `RzChromatic64.dll` (и старую
`RzChromaSDK64.dll`), при отсутствии открывает официальную загрузку Razer и не
запускает Razeru раньше времени.

На уровне продуктов минимальная зависимость — Chroma App. Его App Engine/Common,
службы SDK и драйверы устройств управляются установщиком Razer и не должны
удаляться по отдельности. Synapse, Axon, Cortex и THX Spatial Audio не нужны.
См. `docs/RAZER_REQUIREMENTS.ru.md`; релиз следует проверять без установленного
Synapse и с подключённой целевой клавиатурой.

Рабочие релизы следует подписывать организационным сертификатом: `Razeru.exe`,
`RzruUI.dll`, инсталлятор и деинсталлятор. Настроенное имя Sign Tool передаётся
параметром `-SignToolName`.

## Контрольный список релиза

1. Проверить `git diff`, лицензии зависимостей и метаданные версии.
2. Собрать и проанализировать `Release|x64`, разобрать все предупреждения.
3. На реальном оборудовании проверить раскладки, настройки, блокировку сеанса и
   автозапуск.
4. Собрать инсталлятор, проверить подписи и SHA-256.
5. Под обычной учётной записью Windows 10/11 проверить чистую установку,
   обновление с сохранением настроек и удаление.
6. Подписать собственные PE-файлы и опубликовать контрольную сумму.
7. Создать тег точной ревизии исходников, из которой получены бинарные файлы.

Автоматических модульных/интеграционных тестов и CI пока нет. Их следует добавить
до крупных рефакторингов и полностью автоматизированных релизов.
