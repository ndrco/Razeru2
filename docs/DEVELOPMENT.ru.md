# Руководство разработчика Razeru 2

## Архитектура

| Компонент | Назначение |
| --- | --- |
| `main.cpp` | Скрытое окно, значок, опрос раскладки и клавиатурный hook |
| `ChromaPlaying.*` | Тайминг анимаций, наложения и жизненный цикл |
| `ChromaFileReader.*` | Защищённое чтение клавиатурных `.chroma` версии 1 |
| `ChromaMouseFileReader.*` | Защищённое чтение Mouse 9×7 и ячейки логотипа |
| `RazerHidDevice.*` | Поиск через SetupAPI и HID feature reports Razer |
| `RzruUI/` | MFC-библиотека настроек и изменение `Razeru.json` |
| `tools/RazeruHidTest.cpp` | Независимая аппаратная диагностика |
| `tests/ChromaFileReaderTests.cpp` | Проверка всех анимаций и битого ввода |

Исполняемый файл больше не линкуется с Razer Chroma API и не загружает
`CChromaEditorLibrary64.dll`. Во время работы ему нужны только API Windows и
среда Visual C++. Старые исходники в `Razer/` оставлены для типов, истории и
лицензионного происхождения, но исключены из сборки Razeru 2.

## HID-профиль

`RazerHidDevice` перечисляет HID-класс и принимает два точных профиля:

- Huntsman V2 TKL: `1532:026B`, `MI_03`, usage `000C:0001`;
- Viper: `1532:0078`, `MI_00`, usage `0001:0002`.

91-байтовый feature buffer Windows состоит из report ID и 90-байтового отчёта
Razer. Код проверяет статус ответа, число оставшихся пакетов, класс и ID
команды, а также XOR checksum байтов 3-88. Чтение прошивки использует transaction
ID `0x3F` с безопасным резервным `0x1F` для клавиатуры и `0xFF` с резервным
`0x3F` для Viper. Подсветка передаётся с `0x3F` во временном режиме хранения.

Кадр логической матрицы 6×22 преобразуется в проверенную аппаратную матрицу
Huntsman V2 TKL 6×17. Логические столбцы 1-17 соответствуют аппаратным 0-16,
поскольку нулевой столбец Chroma является отступом. Строки передаются до
включения custom mode; при завершении восстанавливается спектр прошивки.

Viper имеет один элемент — логотип. Из Mouse 9×7 используется координата
`(7,3)`, после чего RGB передаётся командой extended static `0F:02` для
`LOGO_LED=0x04` с `NOSTORE=0x00`. Кадры не записываются во встроенный профиль
мыши. Защищённую Windows коллекцию мыши приложение открывает без generic
read/write; `HidD_SetFeature` и `HidD_GetFeature` при этом остаются доступны.

## Совместимость анимаций

Формат `.chroma` версии 1 читается без DLL Razer. Проверяются тип устройства,
число кадров, точный размер файла, конечность длительности и результат каждого
чтения. Поддерживаются Keyboard 6×22 и Keyboard Extended 8×24. Для расширенного
формата намеренно воспроизводится поведение Razeru 1:
`PluginGetFrameName(..., length=132)` использовал первые 132 цвета в порядке
строк, остальные отбрасывались.
Mouse 9×7 проверяется теми же правилами; для Viper сохраняется только ячейка
логотипа каждого кадра.

## Сборка и проверки

Нужна Visual Studio 2022 с MSVC, ATL/MFC и Windows SDK:

```powershell
.\scripts\build.ps1 -Configuration Release -Platform x64
```

Основная программа линкуется с `hid.lib` и `setupapi.lib`; post-build больше не
копирует бинарные файлы Razer. Полный набор анимаций и повреждённый ввод
проверяет `ChromaFileReaderTests`, железо — `RazeruHidTest`. Аппаратные команды
временные; тест следует заканчивать восстановлением `spectrum`.

Перед выпуском нужно:

1. выполнить чистую сборку Release x64 и проверить зависимости;
2. принять все штатные анимации клавиатуры и мыши и отклонить повреждённый файл;
3. проверить прошивку и цвета на клавиатуре и Viper;
4. проверить смену раскладки, эффекты, настройки, lock/unlock и завершение;
5. запустить без служб, а затем без установленного ПО Razer;
6. собрать инсталлятор и обновить Razeru 1, убедившись в удалении старых
   `CChromaEditorLibrary*.dll` из каталога приложения.

## Инсталлятор

`installer/Razeru.iss` сохраняет прежние AppId, путь установки и mutex, поэтому
Razeru 1 обновляется на месте. В пакет входят только файлы Razeru, конфигурация,
анимации, документация, лицензия и подписанный Microsoft Visual C++ Runtime x64.
ПО Razer не обнаруживается и не предлагается.

Рабочий релиз и Setup следует подписывать Authenticode. Нельзя добавлять общий
профиль устройства без проверки точного product ID, интерфейса, геометрии
матрицы, команд и восстановления состояния на реальном оборудовании.
